# Slice 3.6F-I — Arbitragem runtime sobre decisões WEAK/FALLBACK

## Status esperado no tracker

```text
PENDENTE
```

## Objetivo

Permitir que o V2 validado corrija decisões determinísticas fracas, preservando guardrails fortes.

## Contexto

Hoje uma decisão determinística errada, mas não UNKNOWN, pode impedir interpretação melhor. A promoção só ocorre depois de contrato, validator, shadow, corpus, observabilidade e ações seguras.

## Escopo autorizado

DecisionStrength, gate runtime por flag, templates/read-only tools aprovadas e testes. Não habilitar tools críticas, vector ou planner.

## Implementação

1. Adicionar `Strength` às decisões relevantes.
2. Classificar:
   - STRONG: cancel/human/document/payment guardrails/índice válido;
   - WEAK: broad state, unsupported follow-up inferido, public-table inference;
   - FALLBACK: contextual fallback.
3. Nova flag:
   - `CHAT_OPENAI_TRAVEL_SEMANTIC_ASSIST_ENABLED=false`.
4. Considerar V2 quando:
   - decisão WEAK/FALLBACK;
   - fase elegível;
   - V2 aceito;
   - confidence experimental >= limiar;
   - invariantes válidas.
5. Nunca aceitar override de STRONG.
6. Permitido:
   - templates seguros;
   - availability read-only;
   - route coverage read-only.
7. Proibido:
   - booking_create;
   - payment_create/status;
   - booking_cancel;
   - document_extract;
   - state crítico.
8. Persistir decisão original, proposta V2, validator e decisão final.
9. Rollback instantâneo pela flag.

## Critérios de aceite

- `saindo de Seara` pode vencer broad-state destino.
- coverage pode vencer unsupported fraco.
- institucional pode vencer repetição de tabela.
- STRONG nunca é sobrescrito.
- critical-action violation count permanece zero.
- flag off mantém comportamento anterior.
- no máximo uma chamada V2 por turno.
- sem vector/planner.
